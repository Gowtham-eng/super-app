RefexOne Login — Azure AD / Entra ID Setup

Hand this page to the Azure AD (Microsoft Entra ID) team. This is for RefexOne user login only using OpenID Connect — not SAML.

Protocol: OIDC / OAuth 2.0 App type: Web (confidential client) Not SAML · Not Kissflow SSO

1. Goal

Create one App Registration per company Azure AD tenant so employees can sign into RefexOne with their Microsoft work account.

RefexOne supports multiple Azure AD configurations. Each company / subsidiary with its own Entra tenant needs its own App Registration and must return the values in Section 5.

2. Values RefexOne provides (use these exactly)

Application display name RefexOne Login  (or RefexOne – <Company Name>)
Supported account types Accounts in this organizational directory only (Single tenant)
Platform Web
Redirect URI (required) https://refexone.com/api/auth/azure/callback
Front-channel logout URL (optional) https://refexone.com/login
Grant / flow Authorization Code flow (PKCE supported). Do not enable SAML SSO on this app.
API permissions (Delegated) — Login Microsoft Graph:
openid, profile, email, User.Read
API permissions (Application) — User pull Microsoft Graph Application permission:
User.Read.All
Required so RefexOne can sync/import users from this AD (Extrovis, Kavipharm, etc.).
Admin consent Required for both Delegated and Application permissions — click Grant admin consent for <tenant>
Redirect URI must match exactly (https, path, no extra slash). A mismatch causes Azure error AADSTS50011.

3. Step-by-step in Azure Portal

  1. Sign in to Microsoft Entra admin center (or Azure Portal → Microsoft Entra ID).
  2. Go to App registrations → New registration.
  3. Name: RefexOne Login.
  4. Supported account types: Single tenant.
  5. Redirect URI: select Web and paste https://refexone.com/api/auth/azure/callback → Register.
  6. Open Certificates & secrets → New client secret. Description: RefexOne production. Expiry: 12–24 months. Copy the Value immediately (not the Secret ID).
  7. Open API permissions → Add a permission → Microsoft Graph →
    • Delegated: openid, profile, email, User.Read
    • Application: User.Read.All (needed for RefexOne to pull users)
    Then click Grant admin consent.
  8. (Recommended) Token configuration → Add optional claim → ID → email (and upn if used).
  9. (Optional) Enterprise applications → find RefexOne Login → Assignment required = Yes → assign pilot users/groups.
  10. From Overview, copy Application (client) ID and Directory (tenant) ID.
Do not configure SAML Single Sign-On, Entity ID, or ACS URL for this registration. Those are for other apps. RefexOne login uses OIDC only.
